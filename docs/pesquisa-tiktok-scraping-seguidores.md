# Pesquisa: dá para capturar só a contagem diária de seguidores do TikTok sem API oficial (scraping de página pública)?

Data da pesquisa: 17/09/2026. Contexto: continuação de `docs/pesquisa-tiktok-business-api.md` (rotas oficiais descartadas). Aqui a pergunta é mais estreita: em vez de qualquer API oficial da TikTok, dá para ler só o número de seguidores que já aparece publicamente na página do perfil (`@vonderferramentas`, conta pública, sem login) e, a partir desse único número por dia, calcular localmente o resto do painel — do mesmo jeito que já é feito para o Instagram a partir de `followers_count`?

## Resumo executivo

**Tecnicamente, ler `tiktok.com` direto não funciona mais hoje — testei e o próprio TikTok bloqueia a leitura simples.** Um `GET` HTTP puro (via `curl`, com header de navegador real, sem JavaScript) contra `https://www.tiktok.com/@tiktok` retornou HTTP 200, mas o corpo não é a página de perfil: é uma tela de checagem anti-bot da própria infraestrutura da TikTok (`SlardarWAF`), sem nenhum `SIGI_STATE` ou `__UNIVERSAL_DATA_FOR_REHYDRATION__` — os padrões que funcionavam em anos anteriores parecem não ser mais servidos a quem não passa por essa checagem client-side. Além disso, os Termos de Serviço da TikTok proíbem scraping automatizado de forma explícita e geral (não é uma zona cinzenta de interpretação), e a própria TikTok publica que ativamente combate isso com CAPTCHA, monitoramento de comportamento e rate limiting. Ou seja: essa rota exigiria navegador headless com evasão de anti-bot (manutenção contínua, alto risco de bloqueio de IP) para ler um dado que a própria plataforma não quer que leiam por essa via — desaconselhado.

**A rota que de fato funcionou no teste concreto foi ler a página pública de um terceiro: Social Blade.** Testei via `curl` simples (GET, sem login, sem JavaScript) `https://socialblade.com/tiktok/user/vonderferramentas` — a conta real da VONDER — e o HTML retornado (HTTP 200) já embute, num bloco de hidratação JSON da própria página, os dados atuais exatos da conta (`"followers":"4243","following":0,"likes":"10300","videos":161`) e um histórico recente de seguidores por data (`{"date":"2026-07-31...","followers":4029}` até `{"date":"2026-09-17...","followers":4243}`, 15 pontos). Isso resolve o problema técnico do enunciado — um número diário de seguidores, de graça, sem headless browser, sem anti-bot pela frente — mas é scraping de HTML de um terceiro fora do canal que a própria Social Blade documenta como oficial (Business API paga, por crédito), o que é uma decisão de produto (risco/ToS), não só técnica, ainda que o risco prático aqui seja bem menor que scraping direto da TikTok (nenhuma barreira anti-bot encontrada, `robots.txt` da Social Blade não bloqueia a página). Existe também a Social Blade Business API oficial (`matrix.sbapis.com`, por crédito, não por assinatura) como alternativa "limpa" a esse scraping, provavelmente mais barata que Supermetrics/Metricool para o nosso caso de uso (1 métrica, 1 conta, 1x/dia).

## 1. Scraping direto da página pública do perfil TikTok

**Não funciona hoje via HTTP GET simples — testei e confirmei.**

- Testei `https://www.tiktok.com/@tiktok` de duas formas: (a) via WebFetch, que retornou apenas o texto "Please wait..." (tela de carregamento/checagem); (b) via `curl` com User-Agent de navegador real (Chrome/Windows), sem executar JavaScript — HTTP 200, 1462 bytes, mas o corpo é um script `slardar-config` (`"slardarClient": "SlardarWAF"`, carregando `sdk-web/browser.sg.js` de `sf16-website-login.neutral.ttwstatic.com`), ou seja, uma camada de verificação anti-bot da própria TikTok (WAF com fingerprinting client-side), não a página de perfil. Não há `SIGI_STATE` nem `__UNIVERSAL_DATA_FOR_REHYDRATION__` nem qualquer chave `followerCount`/`follower_count` no HTML retornado — os formatos legados que historicamente permitiam ler dados de perfil só com HTTP GET não estão mais acessíveis dessa forma (ao menos não para uma requisição sem essa camada de verificação satisfeita).
- Ou seja: hoje, ler o perfil exigiria de fato um navegador (headless ou não) capaz de executar o JavaScript da checagem, possivelmente com IP residencial e cookies de sessão — não é mais "GET + parse". Isso já eleva bastante o custo de manutenção (a checagem evolui, quebra sem aviso) e é exatamente o tipo de scraping que a TikTok diz combater ativamente (ver seção 2).
- **oEmbed oficial** (`https://www.tiktok.com/oembed?url=https://www.tiktok.com/@tiktok`): testei, endpoint público, sem autenticação, responde JSON válido (`title`, `author_name`, `author_url`, `html` com blockquote/script de embed) — mas **não inclui contagem de seguidores nem qualquer estatística numérica**, só metadados de identificação.
- **Embed oficial de perfil de criador** ([Embed Creator Profiles](https://developers.tiktok.com/docs/en/embed-creator-profiles?enter_method=left_navigation)): documentação confirma que o widget exibe seguidores/seguindo/curtidas — mas como **HTML renderizado visualmente via `embed.js`**, não como campo JSON parseável na resposta da API. Não dá para extrair o número sem re-renderizar o widget num navegador (ver pergunta 4 abaixo).

## 2. Termos de Serviço e `robots.txt`: o que dizem sobre scraping de página pública, mesmo da própria conta

- Os [Termos de Serviço](https://www.tiktok.com/legal/page/us/terms-of-service/en) da TikTok (versão dos EUA, atualizada em julho de 2026, segundo resultados de busca) **proíbem scraping, crawling, exportação ou extração de dados por sistema automatizado ou bot, de qualquer forma, "except as approved in writing by TikTok USDS Joint Venture"** — a proibição é geral, não distingue dado público de privado, nem conta própria de conta de terceiro. Ler o próprio `follower_count` publicamente visível não está isento dessa cláusula.
- A própria TikTok publica um artigo institucional sobre o assunto — ["How We Combat Unauthorized Data Scraping"](https://www.tiktok.com/privacy/blog/how-we-combat-scraping/en) — confirmando que usam **CAPTCHA, monitoramento de dispositivo/rede/comportamento e rate limiting** contra scraping, deliberadamente sem detalhar todas as táticas "para não ensinar quem tenta contornar". Isso bate com o que observei na prática (item 1): uma tentativa de GET simples já esbarrou numa camada de verificação ativa.
- `robots.txt` (`https://www.tiktok.com/robots.txt`, li o conteúdo literal): bots de IA nomeados (`GPTBot`, `ClaudeBot`, `PerplexityBot`, `anthropic-ai`, `Bytespider` etc.) recebem `Disallow: /` — bloqueio total. Para `User-agent: *` (crawler genérico), o arquivo **não bloqueia explicitamente o caminho de perfil (`/@usuario`)** — bloqueia `/embed/@`, `/auth`, `/inapp`, `/search?`, entre outros, mas não `/@`. Ou seja, pelo texto literal do `robots.txt`, um crawler genérico não estaria automaticamente desobedecendo essa diretiva ao pedir uma URL de perfil — mas isso é irrelevante na prática porque (a) os Termos de Serviço já proíbem por outra via, mais explícita e específica que `robots.txt`, e (b) a barreira anti-bot (item 1) bloqueia funcionalmente antes de qualquer questão de `robots.txt`.
- **Risco prático, sem exagerar nem minimizar:** não há indício de que a TikTok processe judicialmente uma agência pequena por ler uma vez por dia um número já público da própria conta da marca — jurisprudência dos EUA (ex. *hiQ v. LinkedIn*) tende a favorecer scraping de dado público contra alegações de acesso não autorizado. O risco real e concreto, confirmado empiricamente aqui, é **operacional**: a requisição simplesmente não retorna o dado (barreira anti-bot), e insistir com headless browser tende a esbarrar em bloqueio de IP — a busca aponta que bloqueios da TikTok tendem a ser persistentes uma vez acionados. Não é "risco de ser processado", é "não funciona de forma estável e still viola o ToS ao tentar".

## 3. Serviços terceiros com histórico público de seguidores do TikTok (Social Blade e afins)

**Sim, e funcionou no teste — Social Blade rastreia `@vonderferramentas` publicamente, sem login.**

- Testei `https://socialblade.com/tiktok/user/vonderferramentas` via `curl` simples (GET, User-Agent de navegador, sem JavaScript): **HTTP 200**, a página é um app Next.js cujo HTML já vem com um bloco de dados de hidratação contendo, para a conta real da VONDER: `"followers":"4243","following":0,"likes":"10300","videos":161`, `"grade":"B+"`, `"ranks":{"sb":9984,"followers":16243,"likes":14891,"videos":10382}`, `"username":"vonderferramentas"`. **Confirma a conta real da marca, com número exato (não arredondado)** — testei também `@tiktok` (conta enorme) e lá o número vem arredondado para a casa de 100 mil (`95800000`), então o arredondamento parece proporcional ao tamanho da conta; para o porte da VONDER o dado é exato.
- **Histórico diário embutido:** o mesmo bloco de dados trouxe um array de snapshots por data — `{"date":"2026-07-31T00:00:00.000Z","followers":4029}` até `{"date":"2026-09-17T00:00:00.000Z","followers":4243}` — mas **só 15 pontos, com lacunas** (ex.: pula de 06/08 para 09/08, de 15/08 para 18/08). Ou seja, **não é uma série contínua de um valor por dia de calendário**; é a cadência própria de rastreamento da Social Blade (aparentemente ~15 amostras mais recentes que eles têm, não necessariamente uma por dia). Para alimentar o painel da forma pedida (1 número por dia, calcular o resto localmente), o valor **atual** do dia da consulta é confiável; contar com o array de histórico embutido para preencher retroativamente teria buracos.
- **Sem login/chave necessária** para ver esse dado na página pública — bate com o que a busca já indicava (nenhuma autenticação exigida para consulta pontual de perfil).
- **Mas isso ainda é scraping de HTML de terceiro, fora do canal que a própria Social Blade documenta como oficial.** Busquei os Termos de Serviço da Social Blade ([socialblade.com/info/terms](https://socialblade.com/info/terms)): o texto (via busca, não li o corpo integral) indica que a forma de obter volume de dados é por "Custom Reports", pela **Social Blade Business API** (sujeita a Developer Terms próprios) ou por pedido via suporte — sugerindo que extração automatizada recorrente da página HTML pública não é o canal pretendido por eles, mesmo sem um bloqueio técnico equivalente ao da TikTok. Na prática, o `robots.txt` da Social Blade (`https://socialblade.com/robots.txt`, lido literalmente) só bloqueia `/cdn-cgi/` — **não bloqueia a página de perfil** — e nenhuma barreira anti-bot foi encontrada no teste (resposta HTTP 200 direta, sem WAF/CAPTCHA). Ou seja, o risco técnico/operacional aqui é muito menor que scrapear a TikTok direto, mas ainda existe uma diferença entre "o `robots.txt` permite" e "os Termos de Serviço endossam uso automatizado recorrente fora da API paga" — vale a mesma ressalva do documento anterior: decisão de produto, não só de engenharia.
- **Alternativa "limpa": Social Blade Business API.** Confirmei na [documentação de desenvolvedores](https://socialblade.com/developers/docs) (via `curl`, a página carrega sem anti-bot) que existe um endpoint oficial para TikTok — `https://matrix.sbapis.com/b/tiktok/statistics?query=<usuario>` — que exige chave de API/`clientid` e é cobrado **por crédito, por perfil, por plataforma** (não é assinatura mensal fixa como Supermetrics/Metricool). Não confirmei o preço exato do crédito nesta pesquisa (a página não expôs uma tabela de preço em dólares no trecho lido), mas o modelo "pague por consulta" tende a ser mais barato que uma assinatura completa de agregador, já que o uso aqui seria mínimo (1 conta, 1 métrica, 1x/dia). Essa é a rota que resolveria o mesmo problema sem depender de scraping de HTML de terceiro — vale uma checagem manual de preço antes de decidir.
- Não encontrei nenhum outro serviço equivalente (tipo "Social Blade") com evidência de teste direto nesta pesquisa; a busca aponta scrapers de terceiros no Apify que empacotam a própria Social Blade como fonte (reforça que Social Blade é, de fato, a referência pública mais estabelecida para esse dado).

## 4. Widget/embed oficial do TikTok como fonte de dado parseável

**Existe, mas é pensado para exibição visual, não para consumo de dado — na prática não ajuda aqui.**

- O [Embed Creator Profiles](https://developers.tiktok.com/docs/en/embed-creator-profiles) é gerado via oEmbed (mesmo endpoint testado na seção 1) e mostra seguidores/seguindo/curtidas — mas os números só aparecem depois que o script `embed.js` (carregado a partir do `html` retornado) renderiza o card no navegador. O JSON da resposta oEmbed em si (testado, seção 1) **não contém o número** — só metadados (`title`, `author_name`, `author_url`). Ou seja, para extrair o follower count desse widget seria preciso renderizar o embed num navegador real e ler o DOM depois — voltamos ao mesmo problema de precisar de um navegador (headless) descrito na seção 1, sem ganho sobre ler a página de perfil direto.

## Recomendação final

**Não recomendo scraping direto de `tiktok.com`.** Confirmei experimentalmente que hoje isso não é mais "GET + parse": a página é protegida por uma checagem anti-bot ativa da própria TikTok (`SlardarWAF`), então a única forma de contornar seria navegador headless com evasão — manutenção contínua, alto risco de bloqueio de IP (segundo a própria documentação institucional da TikTok, bloqueios tendem a ser persistentes) — em cima de uma proibição explícita e geral nos Termos de Serviço. É o tipo de solução frágil e cara de manter que vai na contramão do princípio de desenvolvimento enxuto deste projeto: o esforço de engenharia (headless browser, rotação de IP, reparo constante quando a checagem mudar) supera de longe o valor de automatizar um único número.

**A rota concretamente viável e testada é ler a página pública da Social Blade para `@vonderferramentas`** — funcionou de primeira, sem login, sem anti-bot, com o número exato da conta real. Isso dá exatamente o insumo que o painel precisa (1 valor de `follower_count`/dia) para calcular localmente crescimento líquido, média por dia etc., do mesmo jeito que já é feito para o Instagram. Dito isso, ainda é scraping de HTML de um terceiro fora do canal que a própria Social Blade documenta como oficial (a API paga por crédito) — um risco de ToS real, ainda que baixo na prática (sem bloqueio técnico observado, `robots.txt` permissivo). Como isso é uma decisão de produto e não só técnica, sugiro ao usuário duas opções concretas, em ordem de preferência:

1. **Automatizar lendo a Social Blade Business API oficial** (`matrix.sbapis.com/b/tiktok/statistics`, por crédito/consulta) — elimina a ambiguidade de ToS de ler o HTML da página, com custo provavelmente baixo para 1 conta/1x-dia. Vale confirmar o preço do crédito antes de implementar.
2. **Se o custo/cadastro da API não se justificar**, automatizar lendo a página pública da Social Blade (testado e funcional) via GitHub Actions, no mesmo padrão do workflow que já existe para Instagram/Facebook/YouTube — aceitando conscientemente que é scraping de terceiro fora do canal "oficial" deles, com risco baixo mas não nulo (a Social Blade pode mudar a estrutura da página ou passar a bloquear a qualquer momento, sem aviso, assim como aconteceu com a TikTok).

Em ambos os casos, o valor lido seria o `follower_count` atual do dia da execução — não recomendo depender do array de histórico embutido na página da Social Blade para preencher datas passadas, porque ele tem lacunas (15 amostras esparsas observadas no teste, não uma por dia).

Se nenhuma das duas opções for aprovada, a recomendação do documento anterior permanece válida: manter o lançamento manual do TikTok (`source: manual`) como caminho vigente.
